## Commands

Install dependencies:

```powershell
npm install
```

Run locally:

```powershell
npm run dev
```

Build:

```powershell
npm run build
```

Deploy is handled by GitHub Actions after pushing to `main`.

Check deploys:

```powershell
gh run list --repo martin9020/calendar --limit 5
gh run watch <run_id> --repo martin9020/calendar --exit-status
```

## Important Rules

- Do not modify Supabase schema, policies, or existing database rows unless the user explicitly asks.
- Frontend changes should preserve existing reservations.
- The app is intentionally open access; do not add login/registration unless explicitly requested.
- Keep Bulgarian UI text consistent with the existing app.
- Prefer small frontend changes in `src/App.jsx` and Supabase API helpers in `src/supabaseClient.js`.
- Do not remove existing CSV import/export behavior.

## Data Model Notes

Reservations are stored as one row per date.

The frontend groups reservations by connected dates and client name for batch editing/counting. This avoids needing a database schema change, but it cannot perfectly distinguish two different back-to-back reservations with the exact same client name.
